# tm ls --json（PR 2）Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** `tm ls --json` 輸出單一 JSON 物件，涵蓋所有 session 與其中的 agent pane，並提供篩選參數與固定的 exit code，讓 Leader Agent 不必解析畫面就能讀取全局狀態。

**Architecture:** `tm ls` 不帶參數時維持現有純文字輸出；帶參數時由 bash 解析並驗證參數，再交給單一 python3 程式。python3 程式自己呼叫一次 `tmux list-panes -a` 與一次 `ps`，讀狀態檔、保護清單、摘要檔與 `.git/HEAD`，合併後序列化。狀態檔的驗證規則從 `_agent_states` 抽成共用的 python 片段 `_PY_STATE_LIB`，fzf 畫面與 JSON 用同一套規則，不會出現兩邊判斷不一致。

**Tech Stack:** Bash（相容 macOS 內建 3.2）、python3 標準函式庫（`-I -S` 執行）、tmux 3.x、`tests/` 下的純 bash 測試。

**Spec:** `docs/design/agent-state-and-orchestration.md` 第 2 節與「實作順序」的 PR 2。

## Global Constraints

- 輸出 schema 頂層：`v`（固定 `1`）、`host`、`generated_at`、`sessions`。
- Session 欄位：`name`、`dir`、`git_branch`、`windows`、`panes`、`clients`、`last_activity`、`protected`、`summary`、`state`、`agents`。
- Agent 欄位：`pane`、`target`、`agent`、`pid`、`session_id`、`state`、`since`、`reason`、`message`、`source`。
- Session 層 `state` 是彙總值：blocked > working > idle > unknown。
- `target` 是可直接餵給 `tmux send-keys -t` 的位址，格式 `<session>:<window>.<pane>`。
- 時間一律 UTC ISO 8601（`YYYY-MM-DDTHH:MM:SSZ`）；沒有值的欄位輸出 `null`，不省略 key。
- `source` 只能是 `hook` 或 `heuristic`。
- 參數：`--json`、`--state <s>[,<s>]`、`--agent <name>`、`--session <name>`、`--no-summary`。
- stdout 只放 JSON，警告與錯誤一律寫 stderr。
- Exit code：0 成功（包含結果為空）、2 指定的 session 不存在、3 參數錯誤、4 tmux server 未啟動。
- `v` 只在破壞相容時遞增；新增欄位不升版。
- 只呼叫 tmux 和 ps 各一次；目標 30 個 session 時 < 200 ms。
- 現有純文字 `tm ls` 輸出不變。

## 本計畫補上的決定（spec 未定）

| 項目 | 決定 | 理由 |
|------|------|------|
| 哪些 pane 列入 `agents` | 有效狀態檔（非 `dead`）或行程樹偵測到 agent，兩者有一即列入 | 只看行程會漏掉經 `npx`、`node cli.js` 啟動的 Claude；只看狀態檔會漏掉 Codex 與未裝 hook 的 Claude |
| `source` | 有效狀態檔 → `hook`；只有行程偵測 → `heuristic`，此時 `state` 為 `unknown` | 本 PR 不做畫面比對；`heuristic` 代表「有 agent，但狀態沒有可靠來源」 |
| 過期的 working | `state` 仍是 `working`，另加 `stale: true`；其他狀態 `stale: false` | 狀態列舉維持 spec 的四個值；`stale` 是新增欄位，不需升版 |
| 行程偵測規則 | `ps -A -o pid= -o ppid= -o args=`；從 `pane_pid` 走行程樹，args 前兩個 token 的 basename 等於 `claude` 或 `codex` 即為 agent，取 BFS 最先找到的行程當 `pid` | 前兩個 token 涵蓋直接執行（`claude …`）與直譯器執行（`node …/codex`、`/bin/bash …/claude`）；比既有 `grep claude` 嚴格，`vim claude.md` 不會誤判 |
| `agent` 值 | 狀態檔的 `agent` 優先，否則用行程偵測結果 | 狀態檔來自 hook，最可靠 |
| `session_id` | 只取狀態檔的值，沒有就 `null` | Codex 的 session id 要用 `lsof` 查，每個 pane 一次 fork，違反效能目標 |
| `pid` | 行程偵測到才有值，否則 `null` | — |
| `--agent` 篩選 | 先移除不符的 agent，沒有 agent 剩下的 session 一併移除；session `state` 依剩下的 agent 重算 | 呼叫端指定 `codex` 時，session 狀態不應被 claude 影響 |
| `--state` 篩選 | 套在 `--agent` 之後；session 有任一 agent 符合就保留整個 session（agent 不刪減）；合法值 `blocked`、`working`、`idle`、`unknown` | 依 spec「只留下含指定狀態 agent 的 session」；沒有 agent 的 session 不會符合 `unknown` |
| 參數形式 | 同時接受 `--state blocked` 與 `--state=blocked`；重複指定時後者生效；`--state` 等篩選參數沒有搭配 `--json` → exit 3 | 篩選只對 JSON 有意義，純文字輸出維持不變 |
| `git_branch` | python 從 `dir` 往上找 `.git`（目錄或 worktree 的 `gitdir:` 檔），讀 `HEAD`；detached 或找不到 → `null` | 每個 session 呼叫一次 `git` 會超出 200 ms 目標 |
| `summary` | `summaries/<name>.jsonl` 最後一行的 `summary`；檔案不存在、壞掉或加了 `--no-summary` → `null` | — |
| `host` | `socket.gethostname()` 取第一段（`Yuan-MBP.local` → `Yuan-MBP`） | 與 spec 範例同為短名稱 |
| 排序 | session 依 `name` 排序；agent 依 window、pane index 的數值排序 | 機器介面需要穩定順序，不跟著最近使用變動 |
| python3 不存在 | stderr 提示、exit 1 | spec 的 exit code 未涵蓋；1 與既有 `_check_cmd` 相同 |

```bash
source "$(dirname "$0")/lib.sh"

# json <python-expr>: evaluate an expression on the JSON read from stdin (bound to d)
json() {
  python3 -c 'import json, sys; d = json.load(sys.stdin); v = eval(sys.argv[1]); print(json.dumps(v) if isinstance(v, (dict, list, bool)) or v is None else v)' "$1"
}

# set_state <target> <state> [payload]: same helper as test_list_state.sh
set_state() {
  local payload='{"notification_type":"permission_prompt"}'
  [[ $# -ge 3 ]] && payload="$3"
  printf '%s' "$payload" | TMUX_PANE="$(pane_id "$1")" "$TM" hook-state "$2"
}

# fake_agent <name>: an executable named claude/codex that just sleeps;
# ps shows it as "/bin/bash <path>/<name>", like node-launched agents
fake_agent() {
  printf '#!/bin/bash\nsleep 600\n' > "$TEST_TMP/bin/$1"
  chmod +x "$TEST_TMP/bin/$1"
}

# agent_pid <name>: pid of the fake agent itself, not tmux's "sh -c" wrapper
agent_pid() {
  pgrep -f "bash $TEST_TMP/bin/$1"
}
```
