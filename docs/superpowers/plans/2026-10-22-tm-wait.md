# tm wait（PR 3）Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** `tm wait` 阻塞到指定 agent 達成 `idle`、`blocked`、`done` 或 `dead` 才返回，讓 Leader 寫出「派工、等完成、收結果」的同步流程，不必自己輪詢。

**Architecture:** 把 `_ls_json` 裡「一次 tmux、一次 ps，產生所有 session 與 agent」的程式抽成共用的 python 片段 `_PY_SNAPSHOT_LIB`，`tm ls --json` 與 `tm wait` 用同一份 agent 判斷。`tm wait` 由 bash 驗證參數後 `exec` 一個常駐的 python3 迴圈：每輪取一次 snapshot、比對條件，等待下一輪時有 `inotifywait` 就監看狀態目錄，沒有就 `sleep`。

**Tech Stack:** Bash（相容 macOS 內建 3.2）、python3 標準函式庫（`-I -S`）、tmux 3.x、選用的 `inotifywait`（inotify-tools）、`tests/` 下的純 bash 測試。

**Spec:** `docs/design/agent-state-and-orchestration.md` 第 3 節與「實作順序」的 PR 3；agent 判斷沿用 PR 2 的「PR 2 決定」。

## Global Constraints

- 語法：`tm wait <target> --until <cond> [--timeout 30m] [--interval 2] [--match any|all] [--after-change]`；`--all` 取代 `<target>`，表示所有 agent pane。
- `<target>`：session 名稱、pane id（`%12`）或 tmux 位址（`web-app:1.0`）。
- `--until`：`idle`、`blocked`、`done`（= idle 或 blocked）、`dead`。
- `--match`：`any`（預設）任一達成即返回；`all` 全部達成。
- `--timeout`：接受 `90s`、`30m`、`2h`；預設不逾時。
- `--interval`：輪詢秒數，預設 `2`。
- Exit code：0 條件達成、1 逾時、2 target 不存在或等待期間變成 `dead`（`--until dead` 除外）、3 參數錯誤；SIGINT → 130，不留暫存檔。
- 返回時 stdout 印出達成條件的 agent，格式與 `tm ls --json` 的 `agents[]` 元素相同，一行一個 JSON 物件。
- 預設條件已符合就立即返回；`--after-change` 記下呼叫當下的 `since`，只接受 `since` 比它新的狀態。
- 有 `inotifywait` 時監看 `~/.tmux-manager/state/`，否則退回 `--interval` 輪詢；兩種模式每輪都檢查 pane 是否仍存在。

## 本計畫補上的決定（spec 未定）

| 項目 | 決定 | 理由 |
|------|------|------|
| 實作語言 | bash 只做參數驗證，迴圈在單一 python3 process 內 | 每輪只呼叫 tmux、ps 各一次；bash 每輪開 python 的成本更高，且要與 `tm ls --json` 共用 agent 判斷 |
| `exec` python | `_cmd_wait` 以 `exec python3` 執行，python 自行安裝 SIGINT handler | 非互動 bash 的背景 job 會繼承「忽略 SIGINT」，bash 無法改回；python 可以，且 `kill -INT <pid>` 直接打到 python |
| Target 解析 | `%N` → 該 pane；含 `:` → `name:W.P` 單一 pane 或 `name:W` 整個 window；其他 → session 名稱完全相符 | tmux 會把 session 名稱中的 `:`、`.` 換成 `_`，不會混淆 |
| 成員 | 每輪重新解析：target 下的 pane 都是成員；pane 存在但還沒有 agent 時，視為「尚未就緒」，不符合任何條件也不算 dead | Leader 剛 `send-keys` 啟動 Worker 就呼叫 wait，此時行程可能還沒出現 |
| `--all` | 成員是所有 session 中「目前有 agent」的 pane | spec 定義為所有 agent pane |
| Target 不存在 | 開始時解析不到 → stderr 提示、exit 2，stdout 為空；等待中 target 消失 → 曾出現有 `pid` agent 的成員一律視為 dead 並輸出（見下一列），沒有的話 stdout 為空，exit 2 | spec：target 不存在回 2；Leader 仍需要知道是哪個 Worker 結束 |
| Dead 定義 | 成員曾在本次等待中出現有 `pid` 的 agent，之後 pane 消失、或 agent 不見、或 `pid` 變成 `null`（hook 狀態失去行程佐證） | PR 2 規定沒有行程時 hook 狀態一律 `unknown`；`kill -9` 不會寫 `dead`，只能靠行程消失判斷 |
| Dead 回報 | 輸出最後一次看到的 agent 物件，`state` 改為 `dead`、`pid` 為 `null`；`--until dead` → exit 0，其他條件 → exit 2（`--match any` 與 `all` 相同） | Leader 需要知道是哪個 Worker 結束 |
| `unknown`、`stale` | `unknown`（含 heuristic）不符合 `idle`、`blocked`、`done`；`stale` 的 working 仍是 working | 不能把沒有可靠來源的狀態當成完成 |
| `--match all` | 至少一個成員有 agent，且所有「有 agent」的成員都符合；尚未就緒的成員不阻擋 | 否則 session 裡一個普通 shell pane 就會讓 `all` 永遠不成立 |
| `--after-change` | 開始時記下每個 pane 的 `since`（ISO 字串，沒有 agent 或沒有 `since` 記為 `null`）；之後該 pane 的 `since` 必須存在且不等於基準值才採信 | `since` 只在狀態改變時更新，「不同」就代表狀態換過；比大小會受秒級精度影響 |
| 逾時輸出 | exit 1，stdout 印出所有有 agent 的成員的目前狀態 | Leader 可以看到誰還在 working |
| 參數驗證 | 全部在 bash：`--until` 必填；`--timeout` 須符合 `^[1-9][0-9]*[smh]?$`（沒有單位視為秒）；`--interval` 須為正數（可有小數，如 `0.2`）；`--match` 只能 `any`、`all`；`<target>` 與 `--all` 必須擇一；未知參數 → exit 3 | 與 `tm ls` 一致，stderr 印原因與 Usage |
| inotify | `inotifywait -qq -t <ceil(interval)> -e close_write,moved_to,create,delete <state_dir>`；`interval < 1` 或狀態目錄不存在時直接 `sleep(interval)` | `-t` 只接受整數；逾時保證每輪仍會檢查 pane 是否存在 |
| tmux server 不存在 | 視為 target 不存在，exit 2 | spec 的 wait exit code 沒有 4 |

## Review Focus

1. **剛送出 prompt 就呼叫 wait**：hook 還沒寫 `working`，狀態仍是上一輪的 `idle`。期望加了 `--after-change` 時不會立即返回。→ Task 2 `test_after_change_ignores_previous_idle`。
2. **Agent 被 `kill -9`**（沒有 `SessionEnd`）：期望 wait 偵測到並 exit 2，不會等到逾時。→ Task 2 `test_killed_agent_exits_2`。
3. **剛啟動、行程還沒出現的 pane**：期望繼續等，不會因為「沒有 agent」就 exit 2。→ Task 1 `test_pane_without_agent_keeps_waiting`。
4. **Session 裡混有一般 shell pane** 時使用 `--match all`：期望一般 pane 不會讓條件永遠不成立。→ Task 1 `test_match_all_ignores_plain_panes`。
5. **在背景執行時按 Ctrl-C**（或收到 SIGINT）：期望 exit 130，沒有殘留的 `inotifywait` 子行程。→ Task 3 `test_sigint_exits_130`。

```bash
test_after_change_ignores_previous_idle() {
  agent_pane new a
  set_state a idle
  local code; "$TM" wait a --until idle --after-change --interval 0.2 --timeout 1s >/dev/null; code=$?
  assert_eq 1 "$code" no-change-times-out
  # since has one-second resolution: let the new working/idle get a different since
  later 1.1 set_state a working
  later 2.2 set_state a idle
  local out; out=$("$TM" wait a --until idle --after-change --interval 0.2 --timeout 6s); code=$?
  wait
  assert_eq 0 "$code" changed
  assert_eq idle "$(json 'd["state"]' <<< "$out")" state
}

test_killed_agent_exits_2() {
  agent_pane new a
  set_state a working

  assert_eq dead "$(json 'd["state"]' <<< "$out")" state
```

```bash
  kill -INT "$pid"

  assert_eq 130 "$code" exit
  sleep 0.3
  assert_eq "" "$(pgrep -f "$TEST_TMP/bin/inotifywait")" no-leftover-watcher
}
```
